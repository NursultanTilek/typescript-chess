# TypeScript Chess with AI

## Project Overview

A fully-featured chess game built with **React + TypeScript + Vite** featuring an advanced AI opponent powered by **Monte Carlo Tree Search (MCTS)** and **AlphaZero-inspired neural networks**.

## Key Features

### 🎮 Chess Game Engine
- **Complete chess rules implementation** including:
  - All piece movements (Pawn, Rook, Knight, Bishop, Queen, King)
  - Special moves: Castling, En Passant, Pawn Promotion
  - Check and checkmate detection
  - Move validation and legal move generation

### 🤖 Advanced AI System

#### Multiple AI Algorithms
1. **Monte Carlo Tree Search (MCTS)**
   - UCB1 formula for node selection
   - Configurable iteration counts based on difficulty
   - Exploration vs exploitation balancing

2. **Minimax with Alpha-Beta Pruning**
   - Traditional search algorithm
   - Move ordering optimization
   - Quiescence search for tactical positions
   - Transposition tables for caching

3. **AlphaZero-Style Neural Network** (Training Mode)
   - Self-play learning
   - Policy and value network
   - PyTorch implementation
   - TensorBoard logging

#### AI Features
- **6 Difficulty Levels**: Beginner, Easy, Medium, Hard, Expert, Master
- **Opening Book**: Pre-programmed opening moves for strong early game
- **Position Evaluation**: Material count, piece-square tables, king safety
- **Move History Tracking**: Analyzes game progression
- **Real-time AI Info Display**: Shows thinking time, search depth, evaluation score

### 🎨 User Interface

- **Lichess.org-inspired design**: Clean, professional chess board
- **Move indicators**: Highlights legal moves and last move
- **Check visualization**: Highlights king when in check
- **Responsive layout**: Board scales properly
- **AI Settings Panel**:
  - Enable/disable AI
  - Adjust difficulty
  - Choose your color (White/Black)
- **AI Info Panel**:
  - Current evaluation
  - Last move details
  - Move history
  - Search statistics

### Key Design Patterns

1. **State Isolation**: Component state uses deep cloning to prevent corruption from AI calculations
2. **Immutable Calculations**: AI search creates independent piece objects for each simulation
3. **Store Pattern**: Zustand for global pieces and history management
4. **Observer Pattern**: React state updates trigger re-renders
5. **Strategy Pattern**: Multiple AI algorithms switchable via difficulty

## Critical Technical Solutions

### Problem: Piece Coordinate Corruption
**Issue**: AI calculations were corrupting piece coordinates on the display board.

**Root Cause**: Shallow copying of Map objects caused piece objects to be shared between:
- Global pieces store
- Component state
- AI calculation state

**Solution**: Implemented `deepCloneBoard()` utility that creates completely independent piece instances with separate coordinate objects.

**Applied in**:
- State initialization (`ChessGamePlay.tsx`)
- AI move safety checks (`Piece.ts`)
- Search algorithms (`search.ts`)
- Board updates (`Board.tsx`)

### Problem: React Re-rendering
**Issue**: Pieces wouldn't move visually after AI moves.

**Root Cause**: React's reference equality check - passing the same Map reference meant React thought nothing changed.

**Solution**: Always create new Map instances when updating state:
```typescript
this.changeBoardCondition(new Map(newPieces))
```

## AI Training (AlphaZero)

Located in `python-training/` directory:

### Training Pipeline
1. **Self-Play**: AI plays against itself generating training data
2. **Neural Network**: Learns from game outcomes
3. **Iteration**: Improved network plays more games
4. **Export**: Trained model can be loaded in TypeScript

### Training Files
- `train.py` - Main training script
- `chess_net.py` - Neural network architecture
- `mcts.py` - MCTS for self-play
- `requirements.txt` - Python dependencies

## Performance Optimizations

1. **Transposition Tables**: Cache position evaluations to avoid recalculation
2. **Move Ordering**: Prioritize captures and center control for better pruning
3. **Iterative Deepening**: Gradually increase search depth
4. **Quiescence Search**: Extend search in tactical positions
5. **Opening Book**: Skip deep search in known opening positions
